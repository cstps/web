# Course 시뮬레이션 정적 그림 렌더링 비교 PoC 결과

작성일: 2026-10-17
대상: 1024.kr Course p5.js 시뮬레이션 그림 문제 자동채점 PoC
브랜치: upgrade/php85-compat

## 1. 목적

Course 시뮬레이션의 `drawing` 모드에서 학생 p5.js 제출 코드를 소스 명령어로 분석하지 않고, 최종 캔버스 렌더링 결과를 정답 렌더링 결과와 비교하여 자동채점할 수 있는지 검증했다.

이번 PoC는 공식 점수를 저장하지 않고 기술 가능성만 확인했다.

## 2. 핵심 원칙

- 학생 브라우저가 계산한 점수, PNG, base64 이미지는 공식 점수로 신뢰하지 않는다.
- 공식 채점은 서버 또는 격리된 신뢰 가능한 실행 환경에서 정답 코드와 학생 제출 코드를 직접 재실행하여 수행한다.
- 정답 코드와 채점 기준은 학생 화면에 노출하지 않는다.
- `starter_code`와 정답 코드는 분리한다.
- 애니메이션 채점은 이번 범위에서 제외하고, 정적 그림만 검증했다.

## 3. 구현·검증된 기반 기능

- `course_simulation_reference` 테이블 추가
- 정답 코드 버전 저장
- 교사용 정답 관리 화면 추가
- 정답 코드 Ace Editor 적용
- 교사용 정답 그림 미리보기 추가
- 학생 접근 차단 확인
- 정답 버전 1·2 저장 확인
- 최신 정답 버전과 학생 제출 코드를 DB에서 읽어 PoC 실행 확인

5. 렌더링 조건
초기 PoC 조건:
- 캔버스 크기: 400×400
- p5.js: 2.3.4
- device_scale_factor=1
- 기본 비교 배경: 흰색 [255, 255, 255]
- 정적 그림만 평가
- 정답과 제출은 각각 독립 page에서 렌더링
전역 모드 function setup()과 new p5(...) 방식 모두 처리 가능성을 확인했다.
같은 page에서 연속 렌더링하면 p5 내부 상태 문제가 생길 수 있어, 정답과 제출은 독립 page에서 렌더링하는 방식을 사용했다.
6. 비교 지표
이번 PoC에서 사용한 지표:
- 전체 화면 일치율
- 전경 합집합 내 일치율
- 전경 영역 겹침률
- 전경 합집합 내 평균 색상 오차
- 다른 픽셀 수
- 정답 전경 픽셀 수
- 제출 전경 픽셀 수
전체 화면 일치율만으로는 채점하면 안 된다.
배경 픽셀 비율이 높으면 빈 화면도 높은 점수로 보일 수 있기 때문이다.
따라서 전경 영역 기준 비교와 영역별 기준이 필요하다.

색상 변경과 도형 누락을 구별할 수 있었다.
7.3 선의 위치 오차
가는 선은 1픽셀 이동에도 픽셀 일치율이 크게 떨어졌다.
선 1픽셀 이동:
전경 내 일치율: 약 28.1%
영역 겹침률: 약 74.2%

따라서 선 채점에는 위치 허용 오차 또는 별도 영역 기준이 필요하다.
7.4 위치 허용 오차
허용 반경 2픽셀 기준:
2픽셀 이동: 100% 인정
5픽셀 이동: 낮은 지표
파란색: 0%
빈 화면: 0%

위치 허용 오차는 작은 좌표 차이를 보정하는 데 효과가 있었다.
다만 굵기 변경, 추가 선, 절반 누락 등은 별도 감점 기준이 필요하다.
7.5 복합 그림
큰 사각형, 작은 원, 가는 선을 함께 그린 그림에서 전체 지표만 쓰면 작은 요소 누락이 가려졌다.
예:
가는 선 누락:
전체 종합 지표: 약 98.97%
선 영역 충족률: 0%

따라서 교사가 지정한 영역별 배점 또는 구성요소별 평가가 필요하다.

11. 결론
정적 그림 자동채점의 기술적 가능성 PoC는 성공으로 판단한다.
성공 근거:
- 정답 코드와 학생 제출 코드를 DB에서 읽음
- 격리 컨테이너에서 네트워크 차단 상태로 재실행함
- p5.js 캔버스를 PNG/픽셀 배열로 추출함
- 오답 제출은 낮은 일치율로 판정함
- 정답 제출은 100% 일치로 판정함
- 운영 DB의 공식 채점 테이블은 변경하지 않음
